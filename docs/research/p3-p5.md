## 0. Shared facts (every phase depends on these)

- **`BrowserWindowKind` is a *data-context* kind, not a window style.** `BrowserDataContext.swift:7-44` has `normal | private` with policy props (`savesSession`, `acceptsOutsideRequests`, `usesAppRecentlyClosed`, …). `BrowserDataContext.kind` (`:57`) is shared by every window on that context, and `BrowserWindowController.kind` is just `dataContext.kind` (`BrowserWindowController.swift:~220`). Little Arc has to share its Space's *normal* context so that ⌘O can move the tab (`BrowserTabMoveRule.allows` needs `tabContext == target.context`, `BrowserTabMove.swift:23-25`). Adding `.little` to `BrowserWindowKind` would therefore give the window its own context. The existing per-window style flag is `isPopup: Bool` (`BrowserWindowController.swift:13-15`, set in `init` at `:131-145`, passed through `BrowserWindowManager.makeWindow(isPopup:)` at `BrowserWindowManager.swift:424-454`). That flag is the natural seam for a window style (normal / popup / little).
- **`hasSpaces` = `currentSpaceID != nil`** (`BrowserWindowController.swift:228`). `init` forces `currentSpaceID = nil` for pop-ups and private windows (`:144`). Many paths branch on `hasSpaces`: rail content, archive `inSpace`, `linkAfterMove`, `openPin`/`openFavorite`, `closeTab`'s linked-tab unload, `archiveIdleTabs`, `restoreArchived`, Space commands (`BrowserCommandContext.spaceWindow`). If Little Arc keeps a Space, every one of these sees it as a full normal window.
- **`isPopup` call sites** are the checklist for a new style: `BrowserWindowManager.swift:264,270,290-293,394,433,461,523,571,791`; `BrowserWindowManager+TabMove.swift:93,161,170`; `BrowserWindowController.swift:245,436,475`; `+Tabs.swift:17-21` (newTab redirect); `+Links.swift:83-91` (insertLinkTab redirect); `+CommandBar.swift:29-40` (Command Bar redirect); `+Navigation.swift:108`; `+Sleep.swift:20`; `+TabMove.swift:24`; `BrowserCommands.swift:360`; `BrowserTabMove.swift:15-35` (+ `Tests/SopranoWebTests/BrowserTabMoveRuleTests.swift`); harness output `SnapshotCommand+Session.swift:732`, `SnapshotCommand+Blocker.swift:167`.
- **Selection model.** `tabs` holds every tab of every Space, in window order. Setting it calls `refreshVisibleTabs()` (`BrowserWindowController.swift:26-29`, `263-280`). `visibleTabs` is the current Space ordered by favorites, then pins, then Today (`BrowserPinLinks.order`). `selectedIndex` indexes `visibleTabs`. `selectedTab` is at `:254-257`.

### Page area for 2–4 panes
- Each tab's web view is pinned to the full `webArea` (`+Tabs.swift:224-235`). `showSelectedTab` hides all but one (`+Tabs.swift:490-492`). `replaceWebView(of:)` (`+Tabs.swift:110-128`, the sleep swap) re-installs with the same full-area constraints. These three places decide where a web view sits. The wake snapshot and crash view pin to `tab.webView` (they follow a pane). The find bar is pinned to the top of `webArea` (`BrowserWindowController.swift:~402-405`).
- The plan says the focused pane is `selectedTab` for every command, Vimium and the CLI. `selectedTab` is `visibleTabs[selectedIndex]`. Panes that are not focused are other tabs, so they read as **not selected** in `sleepCandidate` (`+Sleep.swift:11`), `BrowserArchivePolicy` (`.selected` exemption), `archiveIdleTabs`' `lastActiveAt` reset and every `tab.id == selectedTab?.id` chrome gate (list in `+Navigation.swift:219,247,288,318`, `+Tabs.swift:428-454`, `+TabChrome.swift:103`, `+Zoom.swift:65`, `+Shortcuts.swift:239`, `+PageTools.swift:33`, `+Permissions.swift:37-43`, `+Session.swift:72,126`).

## Commands and key conflicts (⌥⌘N, ⌃⇧=, ⌃⇧-, ⌃⇧1…4, ⌘O)

- Registry: `BrowserCommands.swift:5-36` (`BrowserCommandID`, string ids; stored in `settings.json` `shortcuts`), `:61-120` (`BrowserAppCommand`), `:123-150` `make(…)`, `:213-462` `all` in menu order. Menus (`App/MainMenu.swift`), the Command Bar `/` actions (`+CommandBar.swift:~88-101`) and page-key routing (`+Shortcuts.swift:188-217`) all read the registry. The pattern for numbered commands is `tabCommand` / `spaceCommand` (`:182-210`).
- Shortcut text format: `"opt+cmd+n"`, `"ctrl+shift+="`, `"ctrl+shift+-"`, `"ctrl+shift+1"`, `"cmd+o"`; parser at `BrowserShortcuts.swift:42-120`. ⇧ plus a digit or punctuation is normalized from the shifted character back to the key plus shift (`unshifted` table, `:31-36`); the menu key equivalent uses the shifted character (`keyEquivalent`, `:~230-260`).
- **Conflicts found: none** among default registry shortcuts for `opt+cmd+n`, `ctrl+shift+=`, `ctrl+shift+-`, `ctrl+shift+1…4`, `cmd+o`. The nearest neighbors are `ctrl+1…9` (Spaces, `:200`), `cmd+=`/`cmd+-` (zoom, `:331-334`), `cmd+n`/`shift+cmd+n` (`:221-223`), `ctrl+shift+tab` (`:430`), `opt+cmd+left/right/up/down`.
- Reserved table (`BrowserShortcuts.swift:~205-225`) holds `ctrl+o` (text editing), not `cmd+o`. Vimium's `o`/`O` are unmodified (`VimiumKeyMap.swift:178-179`).
- No `cmd+o` in `App/` menus (no hard-coded `keyEquivalent` literals there).
- [INFERENCE] ⌘O and Esc for Peek or Little Arc are window-contextual. `BrowserCommandContext` (`BrowserCommands.swift:44-58`) passes the controller; `state` closures can enable a command per window style.
- Command Bar ⌥⌘N plus the open-with-Command-Bar path: `.newTab` (`BrowserCommands.swift:214-221`) is the pattern (`showCommandBar(.newTab)`).
