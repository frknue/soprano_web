# Stage 4 P6–P12: code map and API facts

Repo: `soprano-web` on `feat/stage-4`. SDK: `/Library/Developer/CommandLineTools/SDKs/MacOSX26.sdk` (abbreviated `SDK/`). All paths are relative to the repo unless they are absolute. `[INFERENCE]` marks claims I did not observe and that need checking in the dev app.

## Cross-cutting facts (they apply to several phases)

- **Web view construction.** `BrowserWindowController+Tabs.swift:63-97` `makeWebView(context:configuration:)` builds a fresh `WKUserContentController`, then adds the Vimium focus observer and every `BrowserPageScripts.all` script, each in its world (`:72-83`). It sets `isInspectable` and hides the view. The configuration comes from `BrowserWindowManager.swift:630-636` `makeTabConfiguration(for:)`, which sets the data store, `mediaTypesRequiringUserActionForPlayback` and preferences.
- **Binding.** `BrowserWindowController+Tabs.swift:339-363` `bindTab` registers the delegates, the Vimium handler and one `BrowserPageMessageHandler` per `BrowserPageScript.World.allCases` under the name `sopranoWeb`. `:365-381` `unbindTab` calls `removeAllScriptMessageHandlers()`. A new `World` case gets a handler automatically.
- **Swapping user scripts.** WebKit has no per-script removal; the SDK header `WKUserContentController.h:55-59` offers only `addUserScript` and `removeAllUserScripts`. The existing pattern is `BrowserWindowController+Permissions.swift:53-67` `refreshStateScripts`: it filters `userScripts` by a source-prefix marker (`BrowserPermissionScripts.stateMarker`, `BrowserPermissionScripts.swift:12`), removes everything and re-adds the kept scripts. A re-added `WKUserScript` keeps its content world. `WKUserScript` has no URL or host match patterns (`SDK/…/WKUserScript.h:64,72`), so any per-host script must check `location.hostname` itself.
- **Main-frame navigation hook.** `BrowserWindowController+Navigation.swift:386-419` `decidePolicyFor navigationAction` calls `applyContentBlocking(to:pageURL:)` (`:416`) before the load starts. It is applied again on commit (`:251`) and on redirect (`:335`). Per-site script swaps (P7) should hook in at the same three points.
- **CLI.** Parsing is in `BrowserAutomationCommand.swift:78-161` `BrowserCommandRequest.parse`; help text at `:225-294`. The client runs `BrowserCommand.run` at `:300-345`. App-level routing is `BrowserAutomationRouter.perform` at `:412-488`: `windows` and `new-window` are handled before any window is picked, and the remaining commands go to the window's `performAutomation` (`BrowserAutomation.swift:16-299`). The request limit is 16 MiB (`BrowserAutomationSocket.swift:256`); responses can be up to 256 MiB (`:224`).
- **Toast.** `BrowserWindowController+Vimium.swift:10-45` `showVimiumToast(_:)` shows text only and hides itself after 1.5 s. It has no action button.
- **Floating panel pattern.** `BrowserPinEditor.swift:279-330` `BrowserPinEditorPanel` is a borderless `NSPanel` (`isFloatingPanel`, `.floating`, `hidesOnDeactivate`, child window anchored under a view, closes when the user clicks elsewhere). The repo has no `NSPopover` anywhere; this panel is its "Folio popover". `BrowserCommandBarView` and the folder preview (`BrowserWindowController+Rail.swift:344-371`) are in-window overlays instead.
- **Snapshot harness.** It composites overlays at `SnapshotCommand.swift:724-736` (only views whose `window === captureWindow`) and sheets at `:641, :738`. A new child panel needs its own compositing (the pin editor has the same problem).
- **Conflict zones with the P1 agent:** `makeWebView` / `makeTabConfiguration` (where the extension controller is set), `BrowserPageScript.World` (`BrowserPageScripts.swift:8-21`) and `bindTab`.

### API facts: clearing one site's data

- `SDK/…/WKWebsiteDataStore.h:68` `fetchDataRecordsOfTypes:completionHandler:` → Swift `fetchDataRecords(ofTypes:completionHandler:)` / `async dataRecords(ofTypes:)`.
- `:75` `removeDataOfTypes:forDataRecords:completionHandler:` → Swift `removeData(ofTypes:for:completionHandler:)`.
- `WKWebsiteDataRecord.h:83` `displayName`: "usually the domain name". In practice it is the registrable domain (eTLD+1). Removing a record clears that domain **and every subdomain**; per-host granularity isn't possible this way. Match the tab's host with `host == displayName || host.hasSuffix("." + displayName)`. The repo has no public-suffix helper (grep for `registrable|eTLD|publicSuffix` finds nothing).
- For cookies only on the exact host: `httpCookieStore` (`WKWebsiteDataStore.h:85`), `getAllCookies` then `delete` filtered by `cookie.domain`.
- The callbacks arrive on the main thread; the existing code wraps them in `MainActor.assumeIsolated` (`Privacy.swift:63-65`). Reload afterwards with `reload(tab)`.

### Needs a different approach

- **Per-site autoplay is not available through the public API.** Autoplay is `WKWebViewConfiguration.mediaTypesRequiringUserActionForPlayback` (`SDK/…/WKWebViewConfiguration.h:153`), set once per web view at `BrowserWindowManager.swift:633` from the global `AutoplayPolicy` (`BrowserSitePolicies.swift:6-27`). `WKWebpagePreferences` has no autoplay property (`WKWebpagePreferences.h:74-104`: content mode, JS, lockdown, HTTPS only).
  - Option A: recreate the web view when the site's policy differs. `replaceWebView(of:)` (`+Tabs.swift:110-129`) drops back/forward history, so this is not acceptable for navigation.
  - Option B (recommended): set the configuration to the most permissive policy and add a page-world, document-start, per-site state script that blocks `HTMLMediaElement.prototype.play` and `autoplay` attributes until `navigator.userActivation.hasBeenActive`. It would follow the `BrowserPermissionScripts.mediaMute` pattern (`BrowserPermissionScripts.swift:81-140`). This is best-effort and differs from WebKit's native policy.
  - Option C: leave autoplay global and drop it from the popover.
  - This needs a decision before building.
- **The anchor isn't reachable.** `securityIcon` is `private` in `BrowserToolbarView`. Add an accessor, or have `onSecurityInfo` pass the view.

## P7 — Boosts

### Injection patterns today

- `BrowserPageScripts.swift:3-50`: `BrowserPageScript {source, injectionTime, forMainFrameOnly, world}` and `World { page, isolated }`. `isolatedWorld = WKContentWorld.world(name: "SopranoWeb")` (`:49`), and `all` lists the scripts in order (`:31-44`).
- Content worlds in use: `.page`, `"SopranoWeb"` (isolated). Vimium's focus observer is added without a world, so it runs in the page world (`+Tabs.swift:72-76`). Automation `eval` uses `.page` (`BrowserAutomation.swift:313-324`).
- Message rules (`BrowserWindowController+PageMessages.swift:16-55`): `handlePageMessage` switches on `(type, world)`, and each type is accepted from exactly one world. Page-world messages are untrusted input. All handlers share the name `sopranoWeb` (`BrowserPageScripts.messageName`, `:47`).
- The script source style is an IIFE that guards on `window.webkit.messageHandlers.sopranoWeb`, e.g. `BrowserPermissionScripts.swift:22-72`.

### How Boosts fit

- **A dedicated Boost world**, e.g. `WKContentWorld.world(name: "SopranoWebBoost")`. **Do not add it to `World.allCases`.** Doing so would register a `sopranoWeb` handler in a world that runs user code, and user code could post messages that look like ours. Add Boost scripts in `makeWebView` and swap them with a marker prefix (e.g. `/* soprano-web:boost */`) using the `refreshStateScripts` filter-and-re-add pattern. Both swaps call `removeAllUserScripts`, so each must keep the other's marked scripts.
- **Per host:** each script starts with `if (location.hostname !== "<host>") return;`, because `WKUserScript` has no match patterns. Optionally swap scripts at the decide-policy, commit and redirect points used by `applyContentBlocking`. New scripts only affect the **next** document; to apply an edit live, also run `evaluateJavaScript(_:in: nil, in: boostWorld)` (Swift overlay: `SDK/…/WebKit.swiftmodule/arm64e-apple-macos.swiftinterface:66`).
- **CSS at document start:** at `.atDocumentStart`, `document.documentElement` may not exist yet. Insert into `document.head || document.documentElement`, falling back to a `MutationObserver` until it exists. Pages with a strict `style-src` CSP may block an inserted `<style>`. Constructable sheets (`new CSSStyleSheet()` + `document.adoptedStyleSheets`) avoid CSP, but whether that works from an isolated world needs checking `[INFERENCE]`. The private `_WKUserStyleSheet` is not an option.
- **Zap mode** (hover outline, click to hide, Esc ends) should be a trusted isolated-world script (`.isolated`) that posts `zapPick {selector}`, plus a new `case ("zapPick", .isolated)` in `handlePageMessage`. The page's own key handling: see `BrowserShortcutScripts.keyReport` (`BrowserPageScripts.swift:43`).
- **Storage:** follow `BrowserSitePermissionStore` (JSON via `JSONFile.read/write`, tolerant decoding, `changes` observers) under `BrowserFiles.supportDirectory()`. The plan doesn't say whether Boosts are per profile or app-wide (Arc: global).

### CLI

- **Route at manager level.** Add `case "boost"` in `BrowserAutomationRouter.perform` before the window is picked (`BrowserAutomationCommand.swift:415-436`), so it works with no window open. That also keeps it out of `commandsWithoutPage` (`BrowserAutomation.swift:9-12`).
- **`<file|->` must be read client-side.** `-` means the CLI's stdin. Read it in `BrowserCommand.run` (`BrowserAutomationCommand.swift:300-…`) or `parse`, resolving relative paths against `PWD` as `screenshot` does (`:114-120`), and send the content as an argument. The 16 MiB request limit is ample.
- Add the usage lines to `BrowserCommand.help` (`:225-294`).

## P8 — Capture

### SDK facts

- `takeSnapshot` (`SDK/…/WKWebView.h:429`): Swift `takeSnapshot(with: WKSnapshotConfiguration?, completionHandler: (NSImage?, Error?) -> Void)`, async `takeSnapshot(configuration:)`. Documented as "a snapshot for the **visible viewport**".
- `WKSnapshotConfiguration.rect` (`WKSnapshotConfiguration.h:39-43`): "This rect **should be contained within WKWebView's bounds**"; a null rect means the bounds. **So `rect` cannot be used for full-page capture.** `snapshotWidth` sets the output width in points (`:45-50`). `afterScreenUpdates` defaults to YES (`:52-57`); the sleep snapshot uses NO (`+Sleep.swift:68-70`).
- `createPDF` (`WKWebView.h:440`, refined for Swift): `createPDF(configuration: WKPDFConfiguration = .init(), completionHandler: (Result<Data, Error>) -> Void)` and async `pdf(configuration:)` (swiftinterface `:60, :75`).
- `WKPDFConfiguration.rect` is `CGRect?` in Swift (swiftinterface `:46-51`), in **web page coordinates**. A null rect means "the bounds of the currently displayed web page" (`WKPDFConfiguration.h:36-39`). `allowTransparentBackground` (macOS 14+).
- For a full page, set `rect` explicitly to the document size from JS (`document.documentElement.scrollWidth/scrollHeight`). macOS `WKWebView` has no `scrollView`. Check how `pageZoom` (`WKWebView.h:500`) interacts `[INFERENCE]`.
- Then rasterize the PDF page with `PDFKit` / `CGPDFDocument` at the backing scale. Cap the height: a 1280 pt × 30,000 pt page at 2× is about 614 MB of RGBA. Lazy-loaded images below the fold and `position: fixed` elements render as the page lays them out; nothing scrolls.

### Existing code

- CLI `screenshot <path.png>`: `BrowserAutomation.swift:280-290` → `takeScreenshot` `:386-418` (`takeSnapshot(with: nil)`, TIFF→PNG, creates directories). Error type `BrowserAutomationError.screenshot` (`BrowserAutomationCommand.swift:7,14`).
- **Parse gotcha:** `parse` rewrites `arguments[0]` of `screenshot` into an absolute path (`BrowserAutomationCommand.swift:114-120`). `screenshot --full out.png` would turn `--full` into a path. Pull flags out before resolving the path.
- PDF writer: `BrowserWindowController+PageTools.swift:92-98` `writePDF(of:to:)` uses a default `WKPDFConfiguration()`.
- Downloads folder: `settingsStore.settings.downloadDirectoryURL` (`BrowserModel.swift:193-199`). Use it instead of a hard-coded `~/Downloads`.
- The toast is text-only (`+Vimium.swift:10`); "a toast showing it" with a thumbnail or reveal action needs a new view.
- ⇧⌘2 and ⇧⌘R aren't bound anywhere (grep in `BrowserCommands.swift`; shortcuts are `"shift+cmd+…"` strings, e.g. `:238`). Add the command to the registry at `BrowserCommands.swift:237-…`.
- **Area drag:** an overlay view over `webArea`, then `takeSnapshot` with `rect` = the dragged rect converted to web view coordinates (inside the bounds, so valid).

## P9 — Mini Player and media controls

### Re-parenting a web view (what exists)

- Moving a whole tab: `detachTab` (`+Tabs.swift:249-…`) / `attachTab` (`:186-222`), with `bindTab/unbindTab`. Placing the view: `installWebView` (`:224-235`, **private**, pins four edges to `webArea`). Swapping the view object: `replaceWebView(of:)` (`:110-129`, used by sleep).
- For the Mini Player, move **only the `NSView`**; the tab stays in the list and stays bound, so its delegates and message handlers keep working. `removeFromSuperview()` drops the edge constraints, so moving back must call `installWebView` again.
- **Gotcha 1:** `selectTab(id:)` hides every other tab's web view (`+Tabs.swift:488-490`, `other.webView.isHidden = other !== tab`), and Space switching hides the leaving tab (`+Spaces.swift:38`). Both would hide the view inside the panel, so both need a guard.
- **Gotcha 2:** sleep calls `replaceWebView`. A playing tab is exempt (`BrowserTabSleep.swift:84-91`: `isPlayingAudio` → `.playingAudio`; candidate built at `+Sleep.swift:10-…`), but a muted or paused video in the panel is not. Add an exemption.
- **Gotcha 3:** while detached from every window a web view is idle-scheduled by `WKPreferences.inactiveSchedulingPolicy` (`SDK/…/WKPreferences.h:85-99`, macOS 14+). The move should be immediate.
- **Panel:** the `NSPanel` pattern is at `BrowserPinEditor.swift:279-300` (needs `.nonactivatingPanel` in the style mask, `isFloatingPanel`, `level = .floating`, `collectionBehavior` with `.canJoinAllSpaces`/`.fullScreenAuxiliary`, `becomesKeyOnlyIfNeeded`).
- Alternative worth testing: native PiP via `video.requestPictureInPicture()` / `webkitSetPresentationMode('picture-in-picture')` through `evaluateJavaScript`. It needs a user gesture; that `evaluateJavaScript` counts as one is `[INFERENCE]`. `allowsPictureInPictureMediaPlayback` is iOS-only (`WKWebViewConfiguration.h:188`).

### Audio indicator and state today

- The isolated-world `mediaReporter` (`BrowserPermissionScripts.swift:21-76`) posts `mediaFrame` / `mediaState {frame, audible, gone}`. It listens to `play, playing, pause, ended, volumechange, emptied` (capture phase, debounced 200 ms) and checks `paused/ended/volume/muted` across `audio, video`.
- The page-world `mediaMute` (`:81-140`) exposes `window.__sopranoMedia.setMuted`.
- Handlers: `+Permissions.swift:191-222` (`handleMediaFrame/handleMediaState/updateAudio` → `tab.isPlayingAudio`, `metadataChanged`), mute at `:226-252` and `+Tabs.swift:676-680` `toggleMute`. Model: `BrowserSitePolicies.swift:130-160` (`BrowserTabAudioState`, `BrowserTabMedia {audio, frames}`).
- Native: `requestMediaPlaybackState(completionHandler:)` → `WKMediaPlaybackState` none/paused/suspended/playing (`WKWebView.h:375-382`). `pauseAllMediaPlayback(completionHandler:)` (`:360`) for "close pauses". `setAllMediaPlaybackSuspended(_:completionHandler:)` (`:369`). `closeAllMediaPresentations(completionHandler:)` (`:354`).

### Media Session from page JS

- WebKit's `MediaSession.idl` (WebKit main): `attribute MediaMetadata? metadata; attribute playbackState; setActionHandler(); Promise<undefined> callActionHandler(MediaSessionActionDetails); setPositionState()`.
  - `callActionHandler` is a WebKit-only method. A script can trigger the page's own `nexttrack` / `previoustrack` / `play` / `pause` handlers with `navigator.mediaSession.callActionHandler({action: 'nexttrack'})`.
  - `MediaSessionEnabled` is `defaultValue: true`, status mature (`UnifiedWebPreferences.yaml:4141-4149`), so it is available in WKWebView.
- Metadata (`title`, `artist`, `album`, `artwork[]`) and `playbackState` are native attributes, readable from the isolated world because the DOM is shared `[INFERENCE: check with eval in the dev app]`.
- No event fires when `metadata` changes. Either re-read it on the media events the reporter already listens to (plus a slow timer while playing), or wrap the `metadata` setter in a page-world script. The latter is untrusted, but acceptable for display-only data.
- Whether `callActionHandler` works from an isolated world: `[INFERENCE]`, same check.
- Not covered: Now Playing / `MPNowPlayingInfoCenter` integration for a WKWebView host app. No public WebKit API.

### Rail bottom

- `BrowserVerticalTabsView.swift:136-150`: `scrollToSwitcher` (scroll view bottom → `switcher.top`) / `scrollToBottom`, with the `switcher` pinned to the bottom. The switcher is hidden without Spaces (`:185-193`).
- A media bar slots between the scroll view and the switcher. Retarget `scrollToSwitcher` to the bar's top and pin the bar's bottom to `switcher.top` (or to `bottomAnchor` when the switcher is hidden).

### Translation (SDK)

- **Without SwiftUI on macOS 26 there is only one initializer:** `TranslationSession(installedSource:target:)`. Its source is **non-optional** and it **throws if the language pair is not already installed** (Apple docs). Sessions from it can't download languages, so `canRequestDownloads` is false `[INFERENCE from docs]`.
- `init(installedSource:target:preferredStrategy:)` is macOS 26.4 and **not in this SDK**, so it is out.
- Downloading missing languages needs SwiftUI: `_Translation_SwiftUI` provides `View.translationTask(_ configuration:action:)` / `translationTask(source:target:action:)` and `translationPresentation(...)` (`SDK/…/_Translation_SwiftUI.framework/…/arm64e-apple-macos.swiftinterface:19,29,33`).
- **Recommended flow:** detect the language → `LanguageAvailability().status(from:to:)`.
  - `.installed` → `TranslationSession(installedSource:target:)` → `translations(from:)` in batches.
  - `.supported` → either point to System Settings ▸ General ▸ Language & Region ▸ Translation Languages, or host a tiny `NSHostingView` with `.translationTask` to trigger the system download prompt. AGENTS.md says "no SwiftUI", so the hosting view needs an explicit exception.

### `gh` facts (cli.github.com manual)

- `gh pr list -R OWNER/REPO --state open --limit N --json <fields>` works on **one repository**; without `-R` it uses the current directory's repo, which the app doesn't have. `--search <query>` filters within that repo.
  - JSON fields: `additions, assignees, author, autoMergeRequest, baseRefName, baseRefOid, body, changedFiles, closed, closedAt, closingIssuesReferences, comments, commits, createdAt, deletions, files, fullDatabaseId, headRefName, headRefOid, headRepository, headRepositoryOwner, id, isCrossRepository, isDraft, labels, latestReviews, maintainerCanModify, mergeCommit, mergeStateStatus, mergeable, mergedAt, mergedBy, milestone, number, potentialMergeCommit, projectCards, projectItems, reactionGroups, reviewDecision, reviewRequests, reviews, state, statusCheckRollup, title, updatedAt, url`.
- **A cross-repo "search query" folder (e.g. `review-requested:@me`) needs `gh search prs <query> --json …`, not `gh pr list`.**
  - JSON fields: `assignees, author, authorAssociation, body, closedAt, commentsCount, createdAt, id, isDraft, isLocked, isPullRequest, labels, number, repository, state, title, updatedAt, url`.
  - `statusCheckRollup` and `reviewDecision` aren't available there.
- A suggested minimal set: `number,title,url,author,isDraft,updatedAt` (plus `reviewDecision,headRefName` for `pr list`, `repository` for `search prs`).
- Not signed in: `gh` exits non-zero with "gh auth login" on stderr; show it on the folder row.

### Pin tree

- Model: `BrowserPins.swift:7-24` `BrowserPin`, `:27-77` `BrowserPinFolder {id, name, addedAt, children}`, `:80-111` `enum BrowserPinNode { case pin, folder }`, `:141-…` `BrowserPinTree`.
- Coding: `BrowserPins.swift:395-460`. Folders encode as `{"type":"folder",id,name,addedAt,children}` and pins as `{"type":"pin",…}`. Decoding (`:426-446`) accepts `folder`, `pin` or `bookmark` and **throws for any other `type`**, so `LossyArray` drops the node.
- **Hence a new node case (e.g. `"type":"pullRequests"`) would be deleted by any older build that loads and re-saves `spaces.json`.** It would also touch about 15 `switch` sites (`BrowserPins.swift:72,86,93,199,214,242,258,291,450`; `BrowserPinOutlineCell.swift:139`; `BrowserSpacesMenu.swift:147`; `BrowserStartPage.swift:275`; `+Bookmarks.swift:103`; `+Rail.swift:230,395`; `SnapshotCommand+Pins.swift:182`).
- **Safer:** keep `type: "folder"` and add an optional `source` key (e.g. `{"kind":"githubPullRequests","repo":"o/r"}` or `{"kind":"githubSearch","query":"…"}`) to `BrowserPinFolder` and `BrowserPinNodeKeys`. Older builds read it as a plain folder; re-saving drops `source` but keeps the folder.
  - Keep fetched rows **out of** `children`, in a runtime cache keyed by folder id.
  - Inject them when building outline rows (`BrowserPinOutline.rows`, `BrowserPins.swift:521-532`, used at `+Rail.swift:49`). Mark them read-only: refuse drops into the folder (outline drop logic `BrowserPins.swift:509-…`) and hide edit items in the context menu (`+Rail.swift:229-…`).
- Cells: `BrowserPinOutlineCell.swift:133-164` `configure` (folder branch `:139-148` shows the count from `folder.allPins`, chevron, folder icon). Row type `BrowserRailPinRow` `:5-33`. Expansion state `BrowserSpaceStore.swift:400-421` `BrowserPinUIState.expandedFolders` (`UserDefaults`). Expand toggle `+Rail.swift:176-178` is the "on open" refresh hook.
- Other readers of `children` that would need the cache: start page (`BrowserStartPage.swift:275-…`), Spaces menu (`BrowserSpacesMenu.swift:147-…`), folder preview (`+Rail.swift:344-371`), `BrowserPinTree.entries` (Command Bar and Vimium search).

### Notes for P12

- "make new tab/window" via the standard `make` command (`NSCreateCommand`) needs KVC insertion (`insertObject:inScriptTabsAtIndex:` …) on the container plus a class description. cmux sidesteps this with custom `new window` / `new tab` commands. Choose one.
- `execute javascript` is asynchronous (`evaluateJavaScript`). Use `NSScriptCommand.suspendExecution()` / `resumeExecution(withResult:)` to return the result, and gate it on a new `BrowserSettings` field ("Allow JavaScript from Apple Events", `BrowserModel.swift:130-…`). Return `errAEEventNotPermitted` when it is off, as cmux's `validateScript` does (`AppleScriptSupport.swift:94-103`).
- Properties map to `tab.webView.url`, `tab.displayTitle`, `webView.isLoading`. Lazily restored tabs: use `state.url`/`state.title`, as the CLI does at `BrowserAutomation.swift:79-97`. Spaces: `manager.spaces.spaces`, `switchToSpace` (see `BrowserAutomationRouter.switchSpace`, `BrowserAutomationCommand.swift:595-611`). Private windows: the CLI hides them (`automationControllers`); AppleScript should probably do the same.
